# 🔒 Fingerprint Quality Control System

A real-time, multi-metric **image quality control (QC) pipeline** for contactless
mobile fingerprint authentication. Built as a production-style reference
implementation of **FP-03 — Quality Control** for biometric SDKs: it filters out
defective captures (blur, poor lighting, glare, incomplete/no finger, unclear
ridges) **before** they're passed to heavier downstream models (segmentation,
minutiae extraction, 1:1 / 1:N matching), and tells the user in plain language
exactly what to fix.

## ✨ Features

- **5 independent quality metrics**, each mathematically grounded and individually tunable:
  | Metric | Method | Budget |
  |---|---|---|
  | Blur | Laplacian variance | < 10 ms |
  | Brightness | Grayscale mean intensity | < 5 ms |
  | Glare | Over-saturation pixel ratio | < 10 ms |
  | ROI Completeness | Otsu thresholding + area ratio | < 100 ms |
  | Ridge Clarity | Multi-orientation Gabor filter response variance | < 150 ms |
- **Composite score (0–100)** combining all 5 metrics via configurable weights.
- **Master `quality_gate()`** function — one call in, one structured dict out.
- **Prioritized guidance messages** ("Too dark — turn on your flash...") so the
  user gets one clear instruction, not five simultaneous complaints.
- **Streamlit dashboard** with:
  - drag-and-drop upload
  - live sidebar sliders for every threshold and composite weight
  - an animated composite-score ring, count-up number, and confetti on PASS
  - five glassmorphism metric cards with animated progress bars and PASS/FAIL badges
  - a single prioritized guidance banner
- **Batch tester** (`tests/test_quality.py`) that runs the gate over a labeled
  `good / blurry / dark / glare` dataset and reports detection accuracy + a CSV.
- **100% local, free, and safe** — no external APIs, no paid services, no
  Tailwind/CDN dependencies, no data leaves your machine. SQLite-ready if you
  later want to persist results (not required for the core pipeline).

## 🚀 Getting Started

### 1. Set up the environment

```bash
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS/Linux

pip install -r requirements.txt
```

### 2. (Optional) Generate a quick synthetic dataset

If you don't have your 20 real phone captures ready yet, you can smoke-test the
whole pipeline immediately:

```bash
python tests/generate_sample_dataset.py
```

This fills `dataset/good|blurry|dark|glare/` with 5 synthetic ridge-pattern
images each. **Replace these with your own real phone captures before final
submission** — see Part D of the assignment.

### 3. Run the batch tests

```bash
python tests/test_quality.py
```

Prints a full results table to the console and saves it to
`outputs/test_results.csv`.

### 4. Launch the dashboard

```bash
python run.py
# or directly:
streamlit run ui/quality_app.py
```

Then open the local URL Streamlit prints (usually `http://localhost:8501`).

## 🧠 How It Works

1. `app/metrics.py` — each metric is a small, pure function:
   `check_blur`, `check_brightness`, `check_glare`,
   `check_roi_completeness`, `check_ridge_clarity`. Every function is wrapped
   in a `@timed(...)` decorator (see `app/utils.py`) so you can verify the
   sub-millisecond/sub-100ms performance budgets in `outputs/logs/qc_pipeline.log`.

2. `app/quality_assessment.py` — normalizes each raw metric into `[0, 1]`,
   combines them into a weighted composite score, decides pass/fail, and
   resolves a single prioritized guidance message via `quality_gate()`.

3. `ui/quality_app.py` — a thin presentation layer. It never re-implements
   any QC logic; it only calls `quality_gate()` and renders the result.

4. `tests/test_quality.py` — runs `quality_gate()` over every image in
   `dataset/<category>/*`, compares the flagged defect against the expected
   category, and reports accuracy.

### Default thresholds (all live-tunable in the UI sidebar)

| Metric | Reject condition |
|---|---|
| Blur | Laplacian variance `< 10.0` |
| Brightness | mean `< 50` (too dark) or `> 210` (too bright) |
| Glare | `> 5%` of pixels with intensity `> 240` |
| ROI | finger occupies `< 15%` of the frame |
| Ridge Clarity | Gabor response score below threshold (default `15.0`) |
| Composite | score `< 60 / 100` |

## 🧪 Testing Methodology

Collect 20 real captures with your phone (10 minutes):

- 5× **good** — clear, well-lit, steady, finger centered
- 5× **blurry** — move your hand slightly during capture
- 5× **dark** — low ambient light / flash covered
- 5× **glare** — point a flashlight/torch directly onto the finger

Drop them into `dataset/<category>/`, then run:

```bash
python tests/test_quality.py
```

The script tells you the detection accuracy per defect type and writes the
full breakdown to `outputs/test_results.csv`.
